## Open questions
1. **Where `parse_log_entries`'s heading/entry split lives.** `closeout.py` already has `decision_entries`/`DECISIONS_HEADING`-style splitting logic for a handoff's `## Decisions` body; `digest.py` needs the same split applied to the whole `docs/decisions/log.md` file (every `### ` heading, not just one section). **Recommendation:** don't import between `closeout.py` and `digest.py` (keeps both single-purpose and avoids the same import-cycle class of issue 0.18 hit with `board.py`/`registry.py`); duplicate the ~5-line split as a local regex in `digest.py`, matching `closeout.py`'s behavior exactly, and note the duplication in the handoff so a future task can extract a shared tiny helper if a third user appears.
2. **Marking "superseded" needs an opt-in convention, since nothing in the log today marks it.** **Recommendation:** an optional `Supersedes: <exact prior heading text>` line inside a decision entry's body (parallel to the existing optional `risk:`/`Decided:`/`Why:` lines); `digest.py` marks the named prior heading superseded in the rendered digest. Every existing log entry lacks this line, so the first real use is whenever a future task's decision actually reverses an older one — the digest still shows all current risk-high entries unmarked until then, which satisfies "a risk-high log entry missing from the digest fails the harness tests" (nothing is missing; nothing is yet marked).
3. **"Standing rules" has no mechanical definition in the log's format.** The log mixes one-off choices with entries that read as ongoing policy (e.g. "US is the first region; India parked", "MVP first"-style decisions). Auto-detecting "ongoing" from prose is unreliable and risks inventing a rule that was never decided. **Recommendation:** the "Standing rules" section of `digest.md` is a short hand-picked list the Phase B builder writes by citing specific risk-high headings already in the log (never inventing new text), and `render_digest` refuses to render a bullet that doesn't cite a real risk-high heading already present — so the only thing a script enforces is "every standing rule traces to a real decision," not which decisions count as standing. The lead can add/remove bullets by editing the citation list in a follow-up without touching `digest.py`.
4. **The board title's example incidents ("the practice-answer leak", "the IN.yaml regex timeout", "red tests pushed to main") don't match any log heading verbatim.** **Recommendation:** treat them as the human's paraphrases of real incidents, not literal headings to search for; the Phase B builder greps the log/review history for the closest real match (candidates identified above) and cites that, or omits the example if no real match is found — per CLAUDE.md rule 8 and the "never invent entries" instruction, a close-but-wrong citation is worse than one fewer example.
