Edmate System Design

19 Oct 2026 · written from build plan v0.3, the ADRs in docs/adr/ and the decision log · how the build team works is in architecture.html

Edmate lets a student pick a teacher and learn with that teacher's AI agent every day. The teacher builds the agent from their own material, decides what each package lets the agent know and do, and teaches live once or twice a month. This page explains how the whole system fits together, in plain words.

Edmate in one minute

The agent teaches like the teacher

It answers only from the teacher's own material, notes and answers, in the teacher's style. It doesn't fill gaps with general knowledge.

Packages decide access

Each package unlocks some modules and skills. Locked material can never reach the AI. Code enforces this, not a prompt.

The teacher stays in the loop

If the material doesn't cover a question, it goes to the teacher. Their answer reaches the student and teaches the agent for next time.

Every agent is tested

Thousands of test conversations check for leaks, safety, accuracy and good teaching before an agent goes live and after every change.

Who uses it

Students

Aged 13 and up, on a phone or laptop. They find a teacher, start a package and chat with the agent: questions, hints, practice, feedback, mock interviews.

Teachers

They upload their material, shape the agent's style, set up packages, answer questions the agent couldn't, and see weekly insights.

Edmate's trust team (staff)

They verify teachers, handle reports and takedowns, review regulated subjects, and respond to safety alerts.

Outside services

AI model providers (Anthropic, plus OpenAI-compatible services such as OpenAI and OpenRouter). Payment providers come last, after the platform is tested.

The big picture

Edmate is built in layers. People use the apps. The apps hand every student message to the harness, the brain of the system. The harness doesn't know anything about databases or AI vendors. It works through ports, which are fixed plugs, and other parts of the system plug real things into them.

Every part shares one dictionary of data shapes, packages/contracts. Changing it needs a written decision record (an ADR) and three reviewers.

Why it's built this way

  • The brain stays clean. The harness can't import the database, the web framework or an AI vendor's code (a hook blocks it). Tests can plug in fake parts, so the whole teaching engine runs in tests with no real AI calls and no cost.
  • Vendors are swappable. Changing an AI provider, a transcription service or a payment provider means writing a new plug, not changing the brain.
  • One language, one box. Everything is TypeScript, and everything runs with Docker Compose on one server. That's simple to run, cheap, and easy for an open-source contributor to start.

What happens when a student sends a message

Every message, which the code calls a turn, goes through the same 11 steps in the harness. Rules run first. A small, cheap AI model is used only when the rules can't decide. The blue steps run at the same time, so the checks add at most about 0.6 seconds before the agent starts answering.

  1. Let it in admit

    Is this a signed-in student? Not too many messages a minute (10 max)? Not too long (4,000 characters max)?

  2. Check access entitle

    The server works out which package the student has. It never trusts a package sent by the browser. Paused or ended packages are refused, and so is a student over the daily message limit (20 in a rolling 24 hours by default). Then it loads the agent, the package, the teacher's style card and the market's locale pack.

    fails closed
  3. Check the message preGuard

    Remove personal details (phone numbers, emails, ID numbers) first, then check for harmful content and attempts to trick the agent.

    runs alongside 4 and 6fails closed
  4. Understand it route

    What does the student want (on task, asking for the answer, off topic, distress)? Have they tried the problem, and was the attempt right, partly right or wrong?

    runs alongside 3 and 6
  5. Care first escalate

    If the student seems to be in distress: a caring reply with helplines for their market, an alert to the trust team, and skip straight to step 11.

  6. Gather what's needed buildContext

    The student's memory and last-session summary, recent messages, and a search of only the modules this package allows (the teacher's own answers rank first). A separate check says whether the question matches a locked module, without ever reading its text.

    search runs alongside 3 and 4
  7. Decide how to teach decide

    Code rules, not the AI, pick the move: ask a question, give a hint, show a worked example, explain, give the solution, check understanding, say it's locked, or ask the teacher. They also pick what the agent must not reveal, which tools it can use and how long the reply may be.

  8. Write the reply generate

    The main AI model writes the reply, streamed word by word, citing the teacher's sources. It can call tools (up to 3 rounds). It stops if the turn costs too much, and tries the backup model once if the provider fails.

  9. Check the reply postGuard

    Did it give away the answer too early? Leak locked material? Say something the teacher's material doesn't support? Give personal investment, medical or legal advice? Break character? If so, rewrite it once, or fall back to a safe reply.

  10. Count the cost meter

    Record the tokens and cost of every AI call against the teacher, package and student.

    background
  11. Save and learn commit

    Save the messages, open a question to the teacher if needed, update what the agent knows about the student, and write a trace of every step.

    background

Speed targets: the harness itself adds under 0.5 seconds (95% of turns, measured with a fake model), and the first word reaches the student within 2 seconds (95% of turns, with real models).

What the student's screen receives

The reply arrives as a live stream (Server-Sent Events). Alongside the words come small structured events: the sources used, the current hint level, a locked notice naming the package that unlocks it, a question sent to the teacher, skill data such as a practice item or interview state, a safety notice, and a replace event if the final check rewrote the reply. Each reply is checked in sentence-sized pieces as it streams, then checked again as a whole before it's marked done.

How a teacher builds their agent

One teacher has one course and one agent in the MVP. Building it is a pipeline. The teacher does the orange steps; the system does the rest in the background and shows live progress.

Each document moves through uploaded → parsed → transcribed → chunked → embedded → ready (or failed). Deleting a document takes it out of the agent's search within 1 minute.

Packages: who can see what

A package is what a student starts: which modules the agent may use, which skills it may offer, how much help it gives, a daily message limit, live classes, a price and an optional trial. The access filter makes sure locked material can't reach the AI. That's built into the code, not left to instructions (ADR-0003).

Locked

The answer is in the teacher's material, but in a module this package doesn't include. The agent says so and can name the package that unlocks it. It never sees the locked text.

Not covered

Nothing in the teacher's material answers it. The agent says so plainly and sends the question to the teacher. It doesn't guess.

  • The server decides access. Access is worked out on the server from the student's subscription, a teacher's preview, or an eval run. Anything the browser claims is ignored.
  • The search can't skip the filter. The search function demands the list of allowed modules, and the database applies it before ranking results. No search without the filter exists anywhere in the code.
  • Locked checks don't read the text. A separate check only answers yes or no: "does this match a locked module?" Even the leak check on replies is plain code comparing word sequences, not an AI call.
  • Skills are filtered too. The agent only gets the tools for skills its package includes.
  • Changes apply on the next message. Access is read fresh every turn, so an upgrade, pause or end takes effect immediately.
  • What counts as a leak: any run of 8 or more words from a locked chunk, or any fact that only locked chunks contain. The target is zero leaks, tested with 200+ attack conversations.

Until payments are built, starting a paid package creates an active subscription with no charge. Everything else about access works exactly the same, so payments only add how a subscription gets paid for (decided 18 Oct 2026).

How the agent teaches

Code and content decide how to teach. The AI carries out a move that the rules already chose, guided by a prompt pack and the teacher's style card.

The help ladder

Each problem starts at rung 0. The agent climbs one rung when the student asks for a hint, pushes for the answer, or gets stuck twice. It goes back to asking questions when the student makes progress. Each package sets the highest rung.

0
Ask a guiding question
1
A nudge
2
A hint about the idea
3
A worked example of a similar problem
4
The solution, then one check question

Rung 4 only happens if the package allows final answers, either always or only after the student has tried. If a package never allows final answers, rung 3 is the top.

Skills

SkillWhat the agent does
ExplainExplains in 150 words or fewer unless asked for more, cites sources, and ends with one question to check understanding.
CoachOne question per reply and never the answer below rung 4.
PracticeQuestions from the teacher's question bank, or new ones at the right level. Answer keys stay on the server.
FeedbackScores the student's work against a rubric and points to the rubric line. It never rewrites the work for them.
Mock interviewPlays an interviewer or examiner from a persona template and the teacher's notes. /pause steps out for coaching, and it ends with a debrief.
RevisionNotes and flashcards from allowed modules only, with sources.
Study planlater Weekly goals that adjust to progress.

What the AI is told, in order

Safety rules → how this skill works → the teacher's style card → the market's rules → the chosen move and the "don't say" list → the teacher's material with sources → a short summary of the student. All the platform prompts carry one version number. Changing any of them bumps the version and must pass the teaching, leak and locked tests.

Ask the teacher

When the material doesn't cover a question, the teacher answers it and the agent learns from it.

  1. The agent says plainly: "That isn't covered in your teacher's material yet. I've sent your question to them; their answer will appear here." It still helps with any parts that are covered.
  2. A question opens in the teacher's inbox. Similar questions from different students are grouped, so the teacher answers once. The teacher doesn't see who asked.
  3. The teacher answers and picks the module it belongs to. The module decides which packages can use the answer.
  4. The answer appears in each student's chat thread as a message from the teacher, with a notification.
  5. The answer becomes a teacher note (ranked first in future searches) and a permanent test case.
  6. Unanswered questions feed the queue for the next live class and the weekly insights.

Safety

Safety is a set of small, separate checks called guards. Cheap rules run first, and a small AI model is used only when the rules can't tell. If a check breaks, it fails closed: the student gets a safe reply, never an unchecked one.

GuardWhenWhat it does
Personal detailsbeforeRemoves phone numbers, emails, card numbers, one-time codes, national ID patterns from the locale pack, and the student's own name, before any AI sees the message.
DistressbeforeKeywords in each supported language and script, then a classifier. Sends a caring reply with local helplines and alerts the trust team.
Harmful contentbeforeThe AI provider's moderation where available, a local classifier otherwise. Blocks and redirects.
TricksbeforeCatches attempts to override the agent, including "pretend I'm on another package". Repeat attempts count against the student.
Answer leakafterStops the agent giving away an answer it was told to hold back.
Locked leakafterPlain code that compares the reply with the locked modules' text.
GroundingafterEvery claim must be backed by the teacher's material or notes, and numbers are recalculated. If not, the reply is rewritten or the question goes to the teacher.
AdviceafterNo personal investment, medical or legal advice. Rewrites to concept-level teaching with a disclaimer. This matters for the personal-finance pilot courses.
PersonaafterKeeps interview and viva characters inside their "must not" list.
ToneafterNo companion behaviour. The agent never claims to be human or to be the teacher.

Alerts: a safety alert goes to the trust team's inbox and email and is retried until delivered. If nobody acknowledges it within 15 minutes, it escalates to the on-call lead.

Languages: the agent teaches in English in both pilot markets. The safety checks still understand Hindi and Hinglish, in Devanagari and in Latin script, because students will type that way.

Memory and progress

  • One memory per student per teacher. What a student does with one teacher doesn't carry over to another.
  • Mastery per topic: a probability that the student knows each topic. It's updated only from scored evidence (check questions, practice items, rubric feedback), never from chatting.
  • Mistakes: tagged only from the teacher's list of common mistakes, plus new tags the teacher approves.
  • Session summary: 60 words or fewer at the end of each session, which the agent reads next time.
  • The student is in control: they can view, reset and export what the agent remembers, and every change is logged.

The AI models

  • Edmate holds the keys. Students and teachers never bring their own. Keys come from the server's environment, are hidden in logs and errors, and are never stored in the database or sent by any API. Only provider plans that don't train on our data are used.
  • Two connectors: Anthropic (Claude) as the main one, and an OpenAI-compatible one that also covers OpenRouter. OpenAI's Whisper does transcription and text-embedding-3-small does search embeddings. One embedding model serves the whole platform.
  • Two tiers: a small model for quick checks and a main model for replies, with a per-agent override and a backup model when a provider errors, times out or rate-limits. A model that fails the safety, leak or locked tests can't be selected. Which model each tier uses is decided after the cost and quality data from task 7.6.
  • Cost controls: the small model only when rules can't decide; a reply-length cap per move; a cost ceiling per message; cached prompts; history summarised after 20 messages; a daily message limit per package; a monthly cost alarm per teacher.
  • Metering: every AI call writes a usage row (teacher, package, student, model, tokens, cost in US dollars). Teacher previews are billed to the teacher, test runs to Edmate.

Quality checks

Evals are scripted test conversations with expected behaviour. They run in two places. In CI, on every code change, recorded model replies are replayed, so there's no cost and no keys. As a publish gate, real models run on every agent before it goes live and after every change to its material, packages or style card.

Each agent also gets its own tests, built at publish from the teacher's question bank, every correction, and locked-content attacks built from its own packages. A fixed mid-tier judge model scores the subjective cases, and humans double-check 10% each release. Every live agent shows a public teaching scorecard from its latest gate run.

Where the data lives

Everything is in one PostgreSQL database. Search vectors live in the same database (pgvector), and files live in S3-style storage reached only through short-lived signed links.

Privacy rules built into the data

  • Every teacher-owned row carries the teacher's id, and every student row the student's id. The query code refuses to run without the right scope, so one teacher can't read another's data.
  • The harness only sees pseudonymous ids. Student names never go to an AI model.
  • Teachers see aggregated insights (groups of 5 or more). They see a student's conversation only if that student chooses to share it.
  • Traces and logs never contain keys or names. A retention job deletes old data, and students can export or delete everything.
  • The repo is public, so a secret scanner blocks keys and personal data at every edit, commit and CI run.

Markets and locale packs

Nothing country-specific is hard-coded. Each market has a locale pack (content/locales/<market>.yaml) with its languages, timezone, currency format, helplines, privacy law, minimum age, data region, grievance contact, payment methods, disclaimers for regulated subjects, and patterns for local ID numbers. Helplines and compliance details are checked by a human.

Pilot markets

The US and India (en-US and en-IN), teaching in English.

Ages

13 and up. In India, 13 to 17-year-olds need verifiable parental consent under DPDP. No under-13 learners.

Pilot subjects

Specific practical skills, such as personal finance, Marketing 101 and starting a side hustle.

How it runs

The whole system is six containers in Docker Compose on one server, in one US cloud region for the pilot. An India region can be added later if speed or data rules need it.

ContainerJob
caddyThe front door: HTTPS and routing to the web app
webThe Next.js app and API. Runs the harness for each turn and streams the reply.
workerBackground jobs from the Redis queue
postgresThe database, with pgvector for search
redisThe job queue and cache
minioFile storage locally, swapped for an S3 bucket in the cloud

The goal for the deploy guide is a fresh server running the demo in under 30 minutes, with backups and a tested restore.

The brain comes first, proven through the CLI and tests, before any screens. Payments come last, after the platform works end to end and the agents are good. Live status is on the board (python3 .claude/skills/board/board.py status).

Glossary

Agent
The teacher's AI tutor, built from their material and style.
Package
What a student starts: the modules and skills the agent may use, help limits, a daily limit, live classes and a price.
Entitlement
The server's answer to "what may this student use right now?", worked out fresh on every message.
Module
A part of the teacher's course. Access is granted module by module.
Chunk
A short piece of the teacher's material, a transcript or a teacher note, with its source (page, slide, heading or timestamp).
Teacher note
A teacher's answer or correction, saved as a chunk that ranks first in searches.
Style card
A 300-word summary of how the teacher explains, what they stress and the mistakes they watch for.
Prompt pack
Edmate's platform instructions for each mode and skill, versioned together.
Locale pack
One file per market: language, helplines, privacy law, age rules, currency, local ID patterns.
Turn
One student message and the agent's reply, run through the 11-step pipeline.
Harness
The brain of the system. It runs turns and holds the teaching, access and safety logic.
Port
A fixed plug the harness uses to reach the outside (database, AI models, alerts). Tests plug in fakes.
Guard
A small safety check that runs before or after the AI writes.
Help ladder
The five levels of help, from a question (0) to the full solution (4).
Eval
A scripted test conversation with an expected behaviour.
Quality gate
The set of evals an agent must pass before it goes live.
ADR
Architecture decision record: a short document in docs/adr/ that records a hard-to-reverse choice.
